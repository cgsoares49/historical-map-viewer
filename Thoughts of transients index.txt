Thoughts of transients index
So in the creation process, when I reach a point in my list where I need tp create a transient/path, I have to decide if I need neet to create a new path, or can use one I created previously. Looking for just the right previously created one is one of most tedious and time-consuming components of the creation process. What I'm doing now is looking at the tangle of lines in a -9998 rendering, finding coordinates for a likely path to use, searching instances of the chosen coordinates, getting the POL number, searching the PAR using the POL number to get dates to check, then rendering each choice to assess how it will work. I maintain an Excel spreadsheet transients which lives within ancient index.xlsx. One option is to abandon reuse anf just create nw paths every time. I fing thes asthetically unpleasing, not to mention wasteful, although it appears I will always have plenty of room in the data files. So my thought is to create an enhanced version of transients, with the addition of key words to allow better search capabilities. The entries would include all the enformation durrently in the transients worksheet, and also include dates the path was used, associated (if any}, paths it adjoins at start and end, tile crossing coords, if any, and the key words, which are well defined geographic locations (cities, usually) on or near the end points and within the path itsel. This information can from consulting POLs, PAR's, cities and transient worksheet. The latter currently has separate entries for paths that are re-used, and these are shown in red. I wish instead that the new data base has a single entry for each unique transient path in the POL files; transient paths  are identified as those items with -9999.0 to -9998.0 date ranges.
