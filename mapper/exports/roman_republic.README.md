# Roman Republic — sample polity polygon export

Generated by `mapper/export_polity_polygons.py` from MAPPER's canonical raw tile data
(`C:\My stuff\mapper\polareas`, `pols`, `coasts`), tiles `125` and `130` only — the only
2 tiles containing Roman Republic geometry.

## Schema

One row (GeoJSON `Feature` / CSV row) per entity per contiguous date-range where its
shape is constant, modeled on the Cliopatria geospatial history database (Bennett et al.
2025, *Scientific Data* 12:247, https://doi.org/10.1038/s41597-025-04516-9):

| Field | Meaning |
|---|---|
| `Index` | Sequential row number, unique across the whole file |
| `Name` | Entity name — the parent polity, or a bare secondary place name (e.g. `Anxur`) |
| `FromYear` / `ToYear` | Year range (negative = BCE), decimal precision preserved |
| `Area` | km², equal-area projection (EPSG:6933), same convention Cliopatria uses |
| `Type` | `"POLITY"` for every row in this sample |
| `References` | Empty in this sample — not yet populated |
| `MemberOf` | Empty for the parent; `"(Roman Republic)"` for each secondary |
| `ColorR/G/B` | See **Color** below |
| `geometry` | Polygon or MultiPolygon, EPSG:4326 (lon, lat) — full in the `.geojson`, truncated to a ~60-char WKT preview in the `.csv` |

114 rows total: 81 for Roman Republic itself, plus 19 "secondaries" (`Antium`, `Anxur`,
`Campania`, `Capena`, `Crustumerium`, `Falerii`, `Ferentinum`, `Ficulea`, `Fidenae`,
`Gabii`, `Garrison`, `Labicum`, `Latin League`, `Lavinium`, `Pontine district`,
`Praeneste`, `Satricum`, `Veii`, `Velitrae`).

## Secondaries (MemberOf)

Sub-regions recorded in the raw data as `"Roman Republic - X"` (e.g. `"Roman Republic -
Anxur"`) already contributed their territory to the Republic's own merged shape (that
hasn't changed — a composite's area intentionally duplicates its members', matching
Cliopatria's own convention), but now each distinct `X` also gets its own row set, run
through the identical union/time-slicing logic scoped to just that name, with
`MemberOf="(Roman Republic)"`. Example: `Anxur` gets its own rows for `-509.4..-507.5`
(matches the historical record directly — Anxur was Roman only briefly before reverting
to Volsci control), then two later re-conquests (`-406.5..-402.5`, `-400.5..-338.5`).
When a secondary changes hands, the parent's own rows naturally pick up a new row too,
reflecting the smaller merged area.

## Color

The parent's color is a flat lookup in `primaries.txt` (Roman Republic = 240,240,160) —
its single "identifying/legend" color. A **secondary's** color is `parent base RGB +
newoffsets.txt[colorIndex]` (clamped to 255), exactly matching how the live MAPPER
renderer resolves it — so a secondary's color is always a distinct-but-related shade of
its parent's, e.g. Anxur = (240,241,167). If the same place later becomes independent
(no longer `"Roman Republic - X"` in the raw data at all), it would get its own base
color instead — that's out of scope for this Roman-Republic-scoped run.

## How this was built

MAPPER's raw data doesn't store standalone polygons. Each map tile holds fixed
vertex-chain geometries ("PAR entries"), each carrying an *ownership history* — when
territory changes hands the boundary line never moves, only the owner label swaps
(this is exactly the mechanism behind the "recolor + erase boundary" trick used when
authoring the map — e.g. Picenum becomes Roman Republic at **-268.6** with the identical
boundary points before and after).

For every year, this script finds every geometry fragment whose current owner is
"Roman Republic", assembles each fragment's ring from the raw POL/CST boundary segments
it references, and unions them into one shape. It then finds every year where that set
of fragments changes and emits one row per resulting interval, merging consecutive
intervals whose unioned shape is identical (e.g. an ownership change elsewhere that
doesn't touch Rome's borders doesn't create a spurious new row).

## Known caveats

- **Excludes transient entries.** Of 391 raw PAR entries labeled "Roman Republic" in
  these 2 tiles, only 68 are real territory — the rest are army/campaign markers (e.g.
  "Roman Republic - Army of Furius Camillus", "Roman Republic - Consular army") that
  MAPPER represents the same way as territory but are not meant to be part of the
  polity's own shape. Most are identified structurally (their boundary data carries a
  special marker date range, `-9999.0, -9998.0`, on the referenced POL segment). A few
  "convenience" transients reuse an *existing real* polity boundary to depict a
  movement instead of digitizing a dedicated path, so the marker date range isn't
  present at all — for these, the descriptor after the dash (`"Army"`, `"Naval"`, more
  to be added as found) is the only signal, so the export also excludes any secondary
  whose name contains one of those keywords. Two specific leaks found and fixed this
  session: a typo (`-9990.0` instead of `-9999.0`) in `pols/130/POL012.PRN` (now
  corrected at the source), and a "Consular army" entry in `polareas/125/PAR010.ASC`
  that's a genuine convenience-reuse case (now caught by the keyword filter).
- **Truncated at -1 (1 BCE).** One tiny entry ("Roman Republic - Garrison", ~200 km²)
  is labeled "Roman Republic" continuously through 280 CE in the raw data — an artifact
  of this MAPPER dataset never introducing a separate "Roman Empire" entity, not a
  historical claim that the Republic persisted that long. The export is capped at -1 to
  match the dataset's own coherent tracked window for this polity (per its bounding
  summary in `geodata.js`) rather than surface that one outlier as if it were meaningful.
- **Scope is 2 tiles only** (lon ~5-24°E, lat 35-45°N — the Italian peninsula and
  Sicily). This is *not* Rome's full extent at its historical peak (~1-2M km² once
  Spain, North Africa, and Greece are included) — those territories live on other
  tiles, out of scope for this sample. Expect areas here to grow from a small patch
  around Rome toward roughly the peninsula's scale (tens of thousands of km²) by -1,
  not Rome's eventual empire-wide size.
- **Decimal-year precision preserved** (e.g. `-268.6`) rather than rounded to whole
  years as Cliopatria's own published table does — this dataset has finer resolution
  and rounding would lose real information.
- `MemberOf` is now populated for secondaries (see above). `References` is still empty —
  not yet built for this test.
